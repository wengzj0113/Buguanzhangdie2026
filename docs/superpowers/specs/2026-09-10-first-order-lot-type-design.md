# 首单手数计算类型设计

## 目标

增加 `FirstOrderLotType` 和 `FirstOrderMult`，让止损后的下一订单组首单手数支持两种算法。默认使用类型 2：只按上一止损订单组的首单手数递增，不把该组已成交网格手数计入首单基准。

## 参数

- `FirstOrderLotType`：默认 `2`。
  - `1`：保持当前逻辑。
  - `2`：使用上一止损订单组首单手数乘倍数。
- `FirstOrderMult`：默认 `2.0`，必须为有限正数。

MT4 使用外部输入参数；MT5 的输入配置、GUI 应用配置、持久化配置签名和 GUI 可编辑字段同步增加这两个参数。Python 行为模型增加同名语义参数。

## 手数算法

设 `Normalize` 为品种最小/最大/步长归一化，`G` 为当前止损订单组的总已成交手数，`C` 为更早已止损订单组总手数之和，`F` 为当前组首单手数。

### 类型 1：兼容原逻辑

止损时先累加当前组总手数：

```text
C = C + G
下一首单 = Normalize(C × 首单手数倍数)
```

预挂反手单、直接市价反手和重启恢复必须使用同一公式。

### 类型 2：新的首单递增逻辑

止损时记录当前组首单手数，下一首单不使用当前组总手数：

```text
下一首单 = Normalize(F × FirstOrderMult)
```

连续止损时，下一组建立后将其首单手数保存为新的 `F`，后续继续按上一组首单递推。当前组网格加仓只影响组总手数和类型 1 的累计值，不影响类型 2 的首单基准。

### 新建独立K线订单组

K线多组模式中新建的独立订单组仍使用基础 `首单手数`，不继承其他订单组的首单或累计值。该订单组内部发生止损反手时，按所选 `FirstOrderLotType` 计算。

## 状态与恢复

单组状态增加当前订单组首单手数，并与累计止损手数一起持久化；多组状态在 `MultiGroupState` 增加相同字段。旧状态没有该字段时使用可恢复的当前总手数/持仓手数作为兼容回退，保证类型 1 行为不变；新建组从实际发送的首单手数初始化。

所有以下路径必须调用统一的下一首单计算函数：

1. 当前组建立反向预挂单；
2. 反向预挂单成交后的组状态更新；
3. 外层止损触发的直接市价反手；
4. `TRANSITION_PREPARED` 重启恢复；
5. 多组订单的反手预挂单和止损反手。

## 失败与边界

- 参数类型只能是 1 或 2；倍数必须为有限正数。
- 手数统一经过现有 `VolumeNormalize`/`VolumeNormalize` 对应 MT4 实现。
- 达到最大反手次数、止盈、资金不足清理和手动重置的状态清空行为保持不变。
- `FirstOrderLotType=1` 的现有测试和默认旧算法必须继续通过；新增默认参数值为类型 2、倍数 2.0。

## 验收标准

- 首组首单仍使用基础首单手数。
- 类型 1 下，当前组首单 0.01、网格后总手数 0.03、首单手数倍数 1.0 时，下一首单为 0.03。
- 类型 2 下，同样场景且 `FirstOrderMult=2.0` 时，下一首单为 0.02。
- 连续两次止损时，类型 2 使用紧邻上一组的首单手数递推，而不是历史累计总手数。
- 单组、多组、预挂单、直接市价反手和重启恢复使用相同算法。
- MT4、MT5、Python 模型和说明文档的参数及语义一致。
