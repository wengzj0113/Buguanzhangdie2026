# 首单点差阈值设计

## 目标

为 MT4 和 MT5 EA 增加一个可选最大点差限制，避免点差超过用户阈值时启动新的首单订单组。

## 已确认规则

- 增加输入参数“最大首单点差”，单位为 points，默认 0。0 表示关闭限制；大于 0 时，仅当前点差小于或等于阈值才可发起首单，超过阈值时不创建首单。
- 限制适用于普通首单市价单、K 线首单双向挂单，以及多组 K 线策略中的各组首单。
- K 线首单挂单仍未成交且当前点差超过阈值时，EA 撤销该首单挂单；点差恢复且该 K 线首单信号仍有效时，可以重新提交挂单。
- 该限制只管理首单入口。反手订单组切换和网格加单不使用此限制；已有订单组的持仓管理、止盈止损、网格管理照常运行。
- MT4 与 MT5 的输入参数、README 和 HTML 手册保持一致。MT5 自定义面板不增加该输入项，参数通过 EA 输入设置。

## 计算和失败处理

- 使用最新 Bid/Ask 报价计算 `ceil((Ask - Bid) / Point)`，与平台通用的整数 points 约定一致。
- 报价不可用或点差无法计算时，首单入口按不可交易处理；管理已存在订单组不受影响。
- 撤销未成交首单挂单失败时保留跟踪状态并在后续 tick 重试，不重复创建另一组首单挂单。
- 对已成交首单不执行点差撤单；成交后转入原有组管理流程。

## 验收条件

- 阈值为 0 时，首单行为与当前版本一致。
- 阈值为正时，点差等于阈值可开首单，点差大于阈值时首单市价单和 K 线首单挂单均被阻止。
- 点差超过阈值时，已挂出的未成交首单挂单会被清除；点差回到阈值内且信号仍有效时，首单挂单可以恢复。
- 反手订单与网格订单不检查最大首单点差；持仓组的管理持续运行。
- Python 自动化测试覆盖边界、禁用值、撤销/恢复规则与两平台源码入口；MT4 和 MT5 源码均编译无错误。
