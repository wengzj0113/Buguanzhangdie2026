# 同时挂出全部网格挂单设计

## 目标

在现有网格加单功能中，首单或反手新组建立后一次性挂出该组所有内部网格挂单，而不是等待第 1 层成交后才挂第 2 层。MT4、MT5 及测试模型保持相同行为。

## 既有参数语义

`网格数量=N` 仍表示从首单锚点到止损/反手边界分为 N 个区间，因此实际网格加单层为 1 到 N-1，最外侧第 N 层继续作为止损/反手边界。例如 N=5 时一次挂出 4 个网格单；不在本次需求中改变参数含义。

## 行为设计

1. 建立新交易组后，遍历所有内部层级。每个未成交层均按该层价格、方向、手数和订单类型创建一个网格挂单。
2. 网格层独立识别和去重。重复 tick、重启恢复或部分挂单失败时，只补齐缺失层，不删除其他层的有效挂单。
3. 任意一层成交后，仅把该层标记为已成交，更新组总手数、最后入场价、止损止盈；其他未成交层继续保留，不因为成交顺序而重新编号或重复挂单。
4. 止盈、止损、反手、手动重置和资金不足清理仍删除该组的全部剩余挂单。
5. 现有 `网格数量<2` 的无网格行为和 N=2 的单内部层行为保持不变。

## 实现边界

- 单组和多组模式都采用按层状态掩码记录已成交网格层，持久化该状态以支持 EA 重启恢复。
- 网格订单增加可识别的层级信息，同时兼容已有仅含 `.Grid` 的订单；按组、方向和预期价格匹配现有订单，保留不同层的挂单。
- 单组和多组的“只保留一个网格挂单”的旧归一化路径改为“每层保留一个”，不得让归一化函数删除其他层。
- MT4 和 MT5 的挂单、成交历史查询分别使用各平台现有交易 API，但对外行为一致。

## 验收标准

- N=5 的首单结果包含 4 个不同层级的网格挂单，层级为 1、2、3、4。
- 任意一个网格层成交后，剩余 3 个未成交层仍存在；再次处理 tick 不增加重复订单，也不等待成交后才创建下一层。
- N=2 只有第 1 层网格挂单，成交后不再创建内部网格单。
- 止盈/止损/反手时所有剩余网格挂单均被删除。
- Python 测试全部通过，MT4 和 MT5 源码均编译成功；MT4 仅允许已有编译警告，不能新增错误或警告。
