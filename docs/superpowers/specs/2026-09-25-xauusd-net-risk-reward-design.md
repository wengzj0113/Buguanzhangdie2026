# XAUUSD 实际净盈亏比与成交成本控制设计（待审阅）

## 目标与边界

当前 EA 使用首单、双向 K 线首单、逆势与顺势网格、止损后的循环反手，以及网格或线性移动止盈。原有距离参数描述的是价格距离，并不等于扣除佣金和滑点后的整轮净盈亏比。本设计增加一套**可选择启用**的成本控制模式；旧模式及原有参数含义保持不变。成本控制模式只针对 XAUUSD 启用，其他品种先保持旧行为。

目标是：新风险暴露发生前计算最差可接受价格、预计净盈亏比和账户货币风险；成交后以真实价格重新计算；无法在有限的止盈调整范围内满足目标时停止新增仓位。它不承诺成交结果或最终实际盈亏比。跳空、断线、服务器止损滑点和费用事后调整均可使结果偏离预算。MT5 成本模式要求对冲账户；净持仓账户在初始化或启用时拒绝该模式，避免多个独立组被合并为一个净仓位。

## 核心定义

- **一轮 cycle**：从空仓建立基础首单开始，到该轮全部订单组平仓并重置结束。止损后的反手仍属于同一轮。K 线多组时每组有独立 cycle ID，账户级风险按所有 cycle 汇总。
- **组 group**：当前方向的一组基础仓位和网格仓位。保持现有循环方向、手数规则、网格价格和外层止损定义。
- **已实现现金净结果**：已实现成交利润，加该轮已实际入账的佣金、手续费和隔夜费；已支付的开仓费用也在这里，不能再次加入预算。买入 Ask、卖出 Bid 的价格影响已在成交利润中，不能再扣一次点差。
- **预计组 TP/SL 结果**：对当前仓位和拟新增的一笔仓位，按实际或允许的最差开仓价、实际可用的组 SL/TP 价位逐笔估算账户货币价格盈亏，再加入**尚未入账**的预计开仓/平仓费用及不利平仓滑点预算。MT5 使用 `OrderCalcProfit`；MT4 使用 `OrderProfit` 的已实现数据与合约规格计算未实现结果，并用已知报价校验。
- **预计整轮结果**：已实现的本轮现金净结果 + 当前组预计价格盈亏 + 尚未入账的预计费用和滑点预算。设 `P = 整轮在 TP 退出的预计净收益`，`L = 整轮在 SL 退出的预计净结果`；`P > 0` 且 `L < 0` 时定义 `R_net = P / abs(L)`。若 `P > 0` 且 `L >= 0`，两个可测结果均非亏损，盈亏比条件视为满足，但仍需通过其他风控；`P <= 0` 为目标不可行。
- **目标净盈亏比 `R_target`**：成本控制模式下 `R_net` 的下限。界面默认“跟随原设定”，即在一轮建立时按该组锁定的原止盈点数除以止损点数得到目标并锁定；当前默认距离得到 1.0。用户也可显式输入正数覆盖。网格和线性移动止盈仍先产生原策略 TP，再受该现金目标约束。
- **滑点预算**：分开保存开仓和止损平仓的不利滑点估计。平仓预算不保证服务器会按预算成交，只用于事前筛选和风险估算。

## 止盈价格求解

原有网格或线性规则先给出策略目标 `TP_strategy`；实际持仓 SL 和经纪商校验后的可用 SL 决定亏损侧金额。求解使 `P >= R_target × abs(L)` 的最接近当前价的 TP，按交易品种 tick size 向有利方向取整。买组取 `max(TP_strategy, TP_required)`，卖组取 `min(TP_strategy, TP_required)`。因此成本控制不会把原策略止盈进一步向当前价拉近。

`TP_required` 只能在 `TP_strategy` 之外移动不超过 `最大止盈补偿点数`，且不得超过 `原组止盈距离 × 最大补偿比例`；两个上限同时生效。初始回测比较补偿比例 10%、20% 和不补偿三档。超过上限属于 `TARGET_INFEASIBLE`，不能通过继续放大手数或无限移动 TP 解决。

每次首单、任一网格成交、反手成交、动态 SL 移动、线性 TP 更新、费用到账或重启恢复后，重新求解和验证。若当前仓位已经存在而目标不可行，保留服务器 SL、撤销所有尚未成交的增仓触发器，冻结该组新增风险；不因为成本检查单独扩大 SL。是否立即平仓由账户级硬风险限制决定，不能仅为追求比例而无条件市价平仓。

## 开仓和滑点约束

成本模式启用时，首单、逆势/顺势网格与反手的**增加风险挂单**不再长期常驻服务器；EA 持久化相同的触发价格与方向并监控报价。持仓的服务器 SL/TP 保持有效。转换只在该作用域完全空仓且无旧挂单时开始；已有订单组继续按原模式管理直至结束。重启后先恢复触发器和 cycle 状态，再允许新下单。

触发时按以下顺序判断：报价有效且未过期；点差在绝对上限和止损占比上限内；当前报价没有越过允许的最差开仓价；包含本笔后预计整轮 `R_net >= R_target`、TP 补偿未超上限、账户风险未超上限；保证金检查通过。任一失败只跳过本次新增仓位，记录具体原因。连续有效报价达到恢复条件后才重新考虑信号。K 线一次模式若同一报价同时满足高低两个触发器，则两边都跳过，避免双向开仓。

最差允许价格：买为触发基准价加 `最大开仓滑点点数`，卖为触发基准价减该点数。MT5 优先使用经纪商支持的有价格上限的执行方式；不支持时使用带允许偏差的市价请求并在成交后核对。MT4 使用发送前报价检查与 `OrderSend` 滑点参数，成交后核对。平台或经纪商执行模式可能不尊重指定偏差，所以**MT4/MT5 都不能声称开仓滑点被绝对封顶**。若实际成交超预算，立即禁止该 cycle 新增风险，先核对服务器 SL/TP 与风险额。

价格止损触发时的反手遵循已有“旧组结束后新组”顺序；成本门槛失败、报价失效或目标不可行时，该轮结束并记录实际亏损，不保留一个会在点差恢复后突然执行的延迟反手。严禁撤销服务器保护 SL 来等待行情变好。

## 点差、费用和风险输入

成本控制模式所需参数：`目标净盈亏比（默认跟随原设定）`、`最大开仓点差点数`、`最大点差占止损比例`、`最大开仓滑点点数`、`预计平仓滑点点数`、`每手往返佣金及费用预算`、`最大止盈补偿点数`、`最大止盈补偿比例`、`单轮最大预计亏损占权益比例`、`全部并行轮次最大预计亏损占权益比例`、`最长报价延迟毫秒`。未填写关键预算时启用成本模式必须配置校验失败，不能默认为零成本。

点差用实时 `(Ask-Bid)/_Point` 计算；有利方向和不利方向都使用同一门槛。候选回测区间为点差占止损距离 5%、8%、10%，补偿比例 0%、10%、20%；**上线数值必须用目标经纪商的 XAUUSD 报价、合约和佣金校准**。费用预算在计算未来费用时使用，实际成交后以成交历史费用替换估计；历史佣金若延迟入账，保留尚未结算的保守估计。记录计划价、触发时 Bid/Ask、成交价、各费用和拒单原因。

账户风险使用所有可能成交的当前组触发器构造**在配置的平仓滑点预算内**的保守上界：至少覆盖无网格成交、仅逆势网格依次成交、顺势网格成交后回撤至 SL、两侧成交后回撤至 SL，以及动态 SL/线性 TP 的状态变化。跳空的实际损失仍可能超过此值。候选风险若超账户限额，不能放置或保留对应触发器。经纪商扩大实际 SL 时重新计算风险；不允许因为自动调整而悄悄超限。

## 状态与失败处理

单组和 K 线多组均持久化 cycle ID、组 ID、触发器、已处理成交标识、已实现现金结果、已收费用、预计未收费用、成本冻结原因和最近一次预算。成交事件去重，重启时按账户历史与持久化映射重建；若经纪商把佣金记为无法归属到订单组的单独账户扣款，继续保留保守佣金预算，并单独报告实际到账与账本差额。无法完整重建费用或组归属时保留仓位保护，但暂停新增风险并输出诊断。配置变严立即阻止新风险；变宽在下一轮生效。旧模式与新模式不能在同一活跃 cycle 中混用。

止盈未成功修改、SL/TP 未回读验证、部分成交、同一 Tick 多触发器、断线重启和删除触发器失败，都保持“先保护现有持仓，后考虑新增风险”的顺序。暂停或冻结不会取消现有服务器 SL/TP。

## 验收标准

1. 固定模式、K 线单组/多组、平均 K 线、长 K 线、布林带、顺势/逆势网格、动态 SL、两种 TP 模式及四种循环序列均经过相同的成本门槛；旧模式开关关闭时行为不变。
2. 单元场景覆盖费用、点差、实际成交滑点、止损滑点预算、网格连续成交、反手后已实现亏损、TP 补偿边界、最小价格跳动、佣金延迟到账、部分成交、双触发和重启。
3. MT4、MT5 编译通过；EA 实盘模拟账户的保护验证不回退，任一成本超标路径不增加仓位。
4. 同一经纪商 XAUUSD 的真实 Bid/Ask Tick 数据和样本外区间比较旧版、成本模式：报告每轮实际净 RR 分布、总净收益、最大回撤、交易次数、漏单率、滑点分布和费用占比。任何“必然达到目标 RR”的表述均视为验收失败。
