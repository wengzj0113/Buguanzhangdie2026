# K线高度模式多订单组设计

## 目标

在“距离模式=K线高度”时增加 `kline_enable_multiple` 参数，允许用户选择单订单组或多个订单组并行运行。固定距离模式不受该参数影响。

## 参数行为

- `kline_enable_multiple=0`：保持当前单订单组逻辑。只要本EA已有持仓或反向/网格挂单，就不建立新的订单组。
- `kline_enable_multiple=1`：K线高度模式中，只要上一根已完成K线 `k1` 的高度满足最小值和最大值限制，且当前K线 `k0` 突破 `k1` 的最高价或最低价，就允许建立新的订单组，即使其他订单组仍有持仓或挂单。
- `Korder_type` 的既有语义保留：0限制同一根 `k0` 只触发一次首单，1允许同一根 `k0` 重复触发首单。该限制按订单组触发事件执行，不改变固定距离模式。
- K线高度模式仍由 `ordertype` 决定突破方向和循环：正向上破开多、下破开空并采用模式一；逆向上破开空、下破开多并采用模式二。此前确认的正向模式方向序列继续执行。

## 订单组隔离

每个订单组必须有唯一组标识，并在订单注释中携带该标识；MT5和MT4均用“订单识别编号+组标识”筛选订单。每组独立保存：

- 首单成交价、最后成交价、当前方向和六单循环索引；
- 本组固定的止损/止盈距离和线性移动止盈极值；
- 反向预挂单票据、预挂单对应循环位置和反手次数；
- 网格已成交层级、下一网格预挂单和本组网格手数；
- 本组总手数、累计亏损手数和下一组手数计算所需的历史状态；
- 当前组的持仓票据/订单筛选依据及生命周期状态。

组A的止盈、止损、反手、网格成交、移动止盈、资金不足清仓或最大反手次数处理，只能影响组A。正常订单组完成止盈时，只删除组A的挂单并关闭组A持仓，不得调用“删除全部挂单/关闭全部持仓”的单组实现。

## 开单与生命周期

1. 每个Tick先扫描并恢复所有组的持仓和挂单状态，再逐组处理止盈止损、反向预挂单成交、网格成交和下一张挂单。
2. K线高度模式入口单独计算 `k1` 高度和 `k0` 突破方向；建立新组时锁定本次高度作为该组止盈和止损距离，后续K线变化不能修改该组距离。
3. 多组模式建立新组时使用独立组状态和组ID。首个全新周期使用基础首单手数；因该组止损进入下一组时，仍按现有累计亏损手数和首单手数倍数规则计算，不读取其他并行组的累计状态。
4. 组内网格单仍使用预挂单链式流程，网格加单不推进六单循环；组内移动止盈只修改该组持仓。
5. 反向预挂单成交优先于市价回退，且同一组同一止损事件只能产生一次切换，继续保留已修复的重复开单保护。
6. 该组止盈后清除本组状态；其他组继续运行。资金不足或达到最大反手次数时，按当前策略的全量清仓规则处理本EA当前品种和订单识别编号下全部订单，清仓完成当前Tick不再开新组，下一Tick重新判断。

## 状态恢复和兼容

- 使用新的持久化组状态记录保存组ID、订单标识和每组运行字段；EA重启后从订单注释、票据及持久化状态恢复。
- 旧版本只有单组全局状态时，启动后先按订单注释识别为一个兼容组；没有可恢复持仓或挂单时从组ID 1开始。
- 组ID只用于本EA订单归属，不改变Magic/订单识别编号的用户配置。
- 当 `kline_enable_multiple=0` 或距离模式为固定距离时，继续走单组兼容路径，确保原有行为、时间窗口和参数语义不变。

## 异常处理

- 组内挂单被取消、过期或拒绝时，只重建该组应有的挂单；不能删除其他组挂单。
- 组内订单查询暂时不完整时，保留该组状态并等待下一Tick重试，不能误判为空组而开新首单。
- 订单发送资金不足时触发现有全量清仓状态机，禁止在同一Tick再次建立任何组。

## 验收标准

- 单组模式回归通过，已有固定距离和K线高度测试结果不变。
- 多组模式能在同一时间存在至少两个组，且每组可使用不同K线距离。
- 组A止盈/止损不会删除、平仓或修改组B的订单。
- 两个组可同时各自维护一个反向预挂单和一个网格预挂单，互不覆盖票据和状态。
- 每个组的K线距离、首单手数、止损后首单、网格手数、循环方向、移动止盈和最大反手计数均独立。
- `Korder_type=0/1` 在多组模式下分别保持同一 `k0` 单次/多次触发语义。
- MT4、MT5源码均编译为0 errors、0 warnings，Python测试和静态检查通过。
