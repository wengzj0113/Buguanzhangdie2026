# 反手订单保护与手数拆分设计

## 目标

修复 MT4/MT5 在止盈止损未成功设置时继续开单、反手订单偶发失败和超过平台单笔手数限制的问题，同时保持现有网格数量语义：网格数量为区间数，实际内部网格层数为 `网格数量 - 1`。

## 已确认规则

反手订单计算出的总手数按以下规则处理：

| 计算总手数 | 行为 |
| ---: | --- |
| `<= 100` | 正常开 1 个订单 |
| `> 100 且 < 200` | 拆成 2 个相等手数的订单，总手数保持不变 |
| `>= 200` | 不执行本次大手数反手，结束当前订单组；删除该组剩余挂单和持仓状态，下一次 Tick 以基础首单手数启动全新订单组 |

平台规定的单笔最大手数按内部常量 100 手执行，不增加用户可调参数。拆单手数按交易品种最小手数步长规范化；在无法精确二等分时，第二单承接最小步长舍入后的余数，确保两单总和等于目标手数且每单不超过 100 手。

## 止盈止损保护

市价开仓、反手挂单成交、网格成交和订单组恢复都必须先确保当前订单组所有持仓拥有有效止盈和止损。设置函数必须返回成功结果，并再次读取实际持仓确认止盈止损非零且接近期望价格。

保护设置失败时：

1. 保留当前订单组和持仓；
2. 不创建反向挂单或网格挂单；
3. 保存可重试状态，在后续 Tick 重试；
4. 记录平台返回错误，便于定位最小距离、交易时段或服务器延迟问题。

只有确认保护成功后，才允许继续挂单或加单。

## 反手订单状态

单组和 K 线多组都支持一笔反手拆成两笔同价、同方向、等手数订单。状态按订单组记录目标总手数、拆单数量和每一笔订单票据；挂单归一化按“同组、同方向、同价、拆单总手数”保留正确订单，不把第二笔合法拆单删除为重复单。

反手拆单建立时逐笔检查结果：

- 已成功的订单保留并记录；
- 失败的订单只在后续 Tick 补建；
- 未达到目标总手数前，不挂网格单、不推进订单组状态；
- 如果当前计算总手数达到或超过 200，不建立拆单，直接结束当前组并清空组状态。

反手挂单成交时，必须等该组目标总手数已经完整成交或状态明确后，才更新循环索引、首单手数和网格状态，避免半成交被当成完整新组。

## 新订单组

达到 `>=200` 手后，当前订单组执行完整结束清理：删除反向挂单和网格挂单、清空累计亏损手数、网格手数、网格成交掩码、循环索引、反手次数和过渡状态。当前 Tick 不再继续开大手数订单；下一次 Tick 按基础“首单手数”重新创建新订单组。

## 网格行为

不改变现有网格定义和同时挂出所有内部层的行为：`网格数量=N` 时，层级为 `1..N-1`。有利方向网格继续与不利方向网格使用相同层数和当前组网格手数。网格成交识别、止盈移动和剩余层保留逻辑继续按每层状态处理。

## 测试与验收

- Python 模型覆盖 100、120、180、200 手边界和新订单组重启；
- 测试止盈保护失败时没有任何反向或网格新订单；
- 测试拆单失败后只补建缺失订单，不重复建立已成功订单；
- 测试 MT4/MT5 源码均包含相同的保护、拆单和组重启路径；
- 全部 Python 测试通过；
- MT4、MT5 编译成功，保留 MT4 原有的 2 个 `OrderDelete` 警告，不新增错误或警告。
