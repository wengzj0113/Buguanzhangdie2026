# 最大反手次数设计

## 目标

为“不管涨跌”EA增加“最大反手次数”参数，默认值为5。每次订单组因止损切换到下一订单组时，反手次数增加一次；达到上限后不再建立下一组反手订单，而是清理本EA全部订单并从下一次Tick重新开始新的首单周期。

## 参数定义

- 参数名称：`最大反手次数`。
- 默认值：5。
- 有效范围：0及以上的整数。
- 计数单位：一次订单组止损后成功切换到下一订单组，计数加1。
- 同向循环衔接也计数，因为它同样会增加订单组和风险敞口。
- `最大反手次数=0`表示首单止损后不建立下一订单组，直接清仓并重新开始。

## 运行规则

首单建立时反手次数为0。例如最大值为5：

```text
首单：第0组
第1次止损切换：第1组，计数1
第2次止损切换：第2组，计数2
第3次止损切换：第3组，计数3
第4次止损切换：第4组，计数4
第5次止损切换：第5组，计数5
第5组再次止损：不再反手，执行全量清仓
```

达到上限后：

1. 删除当前品种和Magic Number匹配的全部反向预挂单与网格挂单。
2. 关闭当前品种和Magic Number匹配的全部多空持仓。
3. 清空累计亏损手数、循环索引、反手次数、网格状态和订单组距离。
4. 清仓未完成时保持清仓状态，禁止开新单。
5. 清仓完成的当前Tick直接结束。
6. 下一次Tick重新按首单规则开始。

固定距离模式重新检查有效操作时间；K线高度模式重新读取上一根已完成K线、检查高度限制并重新判断突破方向。新周期使用基础首单手数，不继承旧周期倍增手数。

## 状态实现

在MT4和MT5分别增加运行时变量`g_reversal_count`，并通过终端全局变量保存，确保EA重启后仍能继续当前订单组的反手计数。达到上限后复用资金不足场景的全量清仓状态机，但使用独立日志说明是最大反手次数触发。

反向预挂单建立前检查当前反手次数；达到上限时不再建立下一张反向预挂单。若已有预挂单在达到上限时成交，EA在发现该新持仓的当前Tick立即执行全量清仓，防止绕过上限。

## 测试验收

- 默认最大反手次数为5。
- 最大值5允许首单后连续建立5个后续订单组。
- 第6次止损不再建立第7个订单组。
- 最大值0时首单止损直接清仓。
- 计数包含同向衔接。
- 清仓完成当前Tick不新开单，下一Tick重新首单。
- 固定模式重新遵守有效时间，动态模式重新遵守K线突破和高度范围。
- 资金不足清仓逻辑不受影响。
- MT4和MT5行为一致。
