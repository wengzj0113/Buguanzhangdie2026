# K线高度模式每根一次首单双向预埋设计

## 目标

当“距离模式”为“K线高度”且“K线开单模式”为“每根一次”时，首单不再突破后市价开仓，而是在上一根已完成 K 线的最高价和最低价同时预埋两张订单。其余模式保持现有行为。

## 行为规则

首单预埋只在以下条件同时满足时启用：

- 距离模式为 `DISTANCE_CANDLE_RANGE`；
- K线开单模式为 `KORDER_ONCE_PER_BAR`；
- 上一根已完成 K 线高度通过最小/最大高度校验；
- 当前处于允许建立首单的时间窗口；
- 当前订单作用域没有持仓或挂单。

预埋方向如下：

| 开单方式 | K线最高点 | K线最低点 |
| --- | --- | --- |
| 正向 | 多单 | 空单 |
| 逆向 | 空单 | 多单 |

两张首单挂单属于同一个 OCO 首单组。一张成交后，立即删除另一张未成交挂单；成交单成为当前订单组的首单，使用该 K 线高度作为锁定的止盈和止损距离，继续进入现有网格、反向预挂单、止盈止损及循环管理。若两张单都未成交，则继续保留并等待价格触发；同一根当前 K 线不重复创建新的首单预埋组。若预埋失败或清理失败，下一次 Tick 重试并避免创建重复订单。

当 K线开单模式为“每根多次”时，保持当前逻辑：等待价格突破上一根 K 线最高/最低点后，以市价创建首单；不创建双向首单预埋。固定距离模式也保持当前逻辑。

## 实现范围

- MT5 与 MT4 源码同步实现。
- 单订单组路径和允许多订单组并行的路径同步实现。
- 为单组/多组状态增加首单双向预埋票据及必要的价格/方向状态，并纳入持久化与重启恢复。
- 首单预埋与后续订单组反向挂单分开识别，避免现有单张反向挂单的状态机误处理首单预埋。
- 成交后采用 OCO 清理；清理未完成前不继续补挂或启动另一首单。

## 测试验收

Python 行为模型和源码契约测试应覆盖：

1. 正向、每根一次：最高点多单和最低点空单同时预埋。
2. 逆向、每根一次：最高点空单和最低点多单同时预埋。
3. 其中一张首单成交后，另一张首单挂单被取消，并只保留一个活动订单组。
4. 每根多次模式仍等待突破并市价开首单，不产生双向首单预埋。
5. 固定距离模式不受影响。
6. MT4、MT5 均包含首单预埋、OCO 和恢复所需的源码结构。

## 风险与边界

- 双向首单预埋只适用于允许同时持有多空挂单的交易环境；交易平台拒绝挂单时沿用现有失败处理并在下一次 Tick 重试。
- 重启或网络异常期间，优先按持久化票据和服务器订单状态恢复；无法恢复时清理本作用域残留挂单，再从下一次 Tick 重新进入首单流程。
- 双向首单预埋不改变现有订单组的手数、距离锁定、最大反手次数和网格规则。
