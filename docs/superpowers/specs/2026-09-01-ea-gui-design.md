# 不管涨跌 EA 图表 GUI 设计规格

**日期：** 2026-09-01  
**范围：** MT4 与 MT5 图表内悬浮 GUI  
**目标：** 在不改变既有交易策略核心逻辑的前提下，为用户提供参数设置、运行状态查看和常用交易操作。

## 1. 设计目标

GUI 直接叠加在 EA 所在的图表上，采用参考图中的深色紧凑悬浮窗口，而不是独立桌面程序或普通网页仪表盘。

目标包括：

1. 用户可以在图表左上角完成主要参数设置。
2. 用户可以快速查看当前方向、订单组、反手次数、持仓/挂单和浮动盈亏。
3. 用户可以执行应用参数、暂停新首单、恢复运行和紧急平仓删挂单。
4. 参数修改具有草稿态，必须点击“应用参数”才提交。
5. 高风险操作有明确的二次确认，避免误触。
6. 界面在完整状态下信息完整，在最小化状态下只占用一条横向状态栏。

## 2. 已确定的外观和布局

### 2.1 窗口位置和尺寸

- 默认固定在图表左上角。
- EA 加载后默认显示完整窗口。
- 完整窗口使用深色背景、浅色文字、蓝色选中状态，与参考图保持一致。
- 窗口不覆盖整张图表，优先保持紧凑；内容过长时在窗口内部滚动，不改变图表布局。
- 标题栏显示“ 不管涨跌 EA ”、最小化按钮和关闭/隐藏按钮。

### 2.2 最小化状态

最小化后收缩为左上角横向状态栏，只保留：

- EA 名称
- 运行状态
- 当前方向
- 反手次数，例如 `BUY · 0 / 5`
- “恢复”按钮

最小化不停止 EA，也不改变交易逻辑。恢复后回到完整窗口，并保留当前所在页面和未应用草稿。

### 2.3 左侧导航

只保留五项核心导航，以保持参考图的紧凑结构：

1. 总览
2. 开仓
3. 距离
4. 网格
5. 风控

订单明细和最近日志不设为独立导航页，放入“总览”页的折叠区域。

## 3. 页面和组件

### 3.1 总览页

总览页是默认页面，显示运行和交易状态：

- 运行状态：运行中、已暂停新首单、初始化中、错误/需处理。
- 当前方向：BUY/SELL/无持仓。
- 当前订单组编号。
- 反手次数与最大反手次数。
- 当前浮动盈亏。
- 持仓数量与挂单数量。
- 当前首单、反向预挂单和网格挂单摘要。
- 参数草稿状态：无修改、存在未应用修改、应用成功、应用失败。
- 可折叠的最近订单和最近日志区域，默认显示最近 5 条。

总览页底部固定显示主要按钮：

- `应用参数`
- `暂停新首单` / `恢复新首单`
- `平仓删挂单`

### 3.2 开仓页

对应现有参数：

- 首单方向
- 循环模式
- 开单方式
- K 线开单模式
- K 线模式是否允许多个订单组并行
- 首单手数
- 首单手数倍数

简洁模式显示首单方向、循环模式、首单手数；专家模式显示全部参数。

### 3.3 距离页

对应现有参数：

- 距离模式
- 固定止损距离
- 固定止盈距离
- K 线最小高度
- K 线最大高度
- 止盈移动模式

动态显示规则：

- 距离模式为“固定距离”时显示固定止损距离和固定止盈距离。
- 距离模式为“K 线高度”时显示 K 线最小高度和最大高度、开单方式、K 线开单模式。
- 止盈移动模式始终显示。

### 3.4 网格页

对应现有参数：

- 网格数量
- 网格手数倍数

同时显示只读说明：首组网格手数、当前组网格手数、已成交网格层级、下一网格价格。

### 3.5 风控页

对应现有参数和运行设置：

- 最大反手次数
- 开始时间
- 结束时间
- 订单识别编号
- 订单注释

风控页显示风险提示：连续止损会增加手数；平仓删挂单会关闭本 EA 当前品种和识别编号范围内的持仓与挂单。

## 4. 简洁模式与专家模式

GUI 提供“简洁模式 / 专家模式”切换，首次打开默认专家模式，用户可以自行切换。

### 简洁模式

只显示常用、低认知负担的参数：

- 首单方向
- 循环模式
- 距离模式
- 首单手数
- 固定止损/止盈或 K 线高度范围
- 开始/结束时间
- 暂停、应用和紧急操作

高级参数以折叠区隐藏，不删除其当前值。

### 专家模式

显示全部现有输入参数，并按五个导航页面分组。专家模式不改变参数含义，只改变可见性。

## 5. 参数修改和生效规则

### 5.1 草稿模型

- GUI 加载时读取 EA 当前参数和运行状态，形成“已应用配置”。
- 用户编辑控件时只修改 GUI 草稿，不立即改变交易逻辑。
- 只要草稿与已应用配置不同，总览页显示“有未应用的参数修改”。
- 点击“应用参数”后执行校验；校验通过才提交配置。
- 校验失败时保留草稿，定位显示错误字段和原因，不影响当前交易状态。
- 应用成功后显示短暂结果提示，并刷新已应用配置。

### 5.2 当前订单组保护

当前订单组中已经锁定的止损/止盈距离、循环、方向、网格和手数等运行参数不被 GUI 静默改写。

应用的新策略参数：

- 对当前订单组不产生破坏性修改。
- 在下一订单组或下一轮首单开始时生效。
- 仅“暂停新首单/恢复新首单”等运行控制立即生效。

如果某个参数无法在当前状态下安全应用，GUI 必须明确显示“已保存，下一轮生效”，而不是显示为已经改变当前订单组。

### 5.3 参数校验

GUI 校验与 EA 的 `OnInit` 校验保持一致，并在提交前给出可读提示：

- 手数必须符合品种最小手数、最大手数和步进。
- 距离、网格数量、最大反手次数等整数参数必须在有效范围内。
- K 线最小高度不能大于最大高度。
- 时间必须符合 `时:分` 格式。
- 订单识别编号和订单注释不能为空或产生非法识别冲突。
- 运行中检测到已有订单时，不允许通过普通参数应用改变当前订单组的关键锁定状态。

## 6. 便捷操作语义

### 6.1 暂停新首单

点击后立即进入“已暂停新首单”状态：

- 禁止建立新的首单/新订单组。
- 已有持仓继续管理。
- 已有反向预挂单和网格挂单继续管理。
- 不修改既有止损、止盈和订单组状态。
- 按钮文字变为“恢复新首单”。

### 6.2 恢复新首单

取消暂停状态。EA 按当前策略规则和交易时间重新判断是否可以建立首单，不强制立即下单。

### 6.3 平仓删挂单

该操作独立于暂停状态，执行前必须弹出二次确认框。确认框明确显示：

> 将关闭本 EA 当前品种和订单识别编号范围内的全部持仓，并删除全部挂单。此操作不可撤销。

确认后调用现有清仓逻辑；如果部分操作失败，GUI 显示失败数量和重试状态，不假报成功。

## 7. 状态颜色和提示

- 绿色：运行中、操作成功、正常持仓状态。
- 蓝色：当前选中页面、普通操作按钮、可恢复状态。
- 黄色：有未应用参数、等待下一轮生效、风险提示。
- 红色：错误、紧急操作、清仓/删除挂单按钮。
- 灰色：暂停、禁用或只读内容。

所有状态提示同时写入总览页最近日志，避免只依赖短暂的颜色或 Toast。

## 8. 实现边界和架构

### 8.1 交易逻辑与 GUI 分离

GUI 只负责展示、收集输入和发出命令，不直接复制订单组算法。交易策略继续由现有 EA 核心逻辑负责。

建议建立以下边界：

- `GuiState`：保存窗口状态、当前页、显示模式、草稿配置和提示状态。
- `GuiView`：创建/更新图表对象，负责布局和控件绘制。
- `GuiEvent`：统一处理点击、输入、下拉选择、最小化、恢复和确认框事件。
- `GuiController`：把 GUI 命令转换为策略层可执行的控制请求。
- `StrategySnapshot`：向 GUI 提供只读的订单、订单组、状态和错误摘要。
- `ConfigDraft`：保存草稿和已应用配置的差异。

MT4 和 MT5 保持相同的页面、字段、命令和状态语义；平台差异只封装在图表对象、输入事件和交易查询适配层中。

### 8.2 图表对象命名

所有对象名称必须带有统一前缀，并包含账户、品种和订单识别编号，避免同一图表或多个 EA 实例互相覆盖。GUI 删除时只清理自己的对象。

### 8.3 生命周期

- `OnInit`：创建 GUI、读取持久化的窗口状态和显示模式、默认显示完整窗口。
- `OnTick`：更新策略快照和只读状态，不在每个 Tick 重建全部控件。
- `OnChartEvent`：处理鼠标、键盘和对象点击事件。
- `OnDeinit`：释放 GUI 对象和资源；不因 GUI 关闭按钮而自动清理交易，关闭按钮只隐藏 GUI。

## 9. 错误处理

- GUI 创建失败：EA 交易逻辑仍按原规则运行，同时在日志和图表 Comment 中报告 GUI 不可用。
- 参数提交失败：保留草稿，显示字段级错误，不改变已应用配置。
- 交易命令失败：显示服务器返回码、简短解释和可重试状态。
- 清仓删挂单未完成：显示“清理中”，持续刷新结果，直到成功或明确报告仍有残留。
- EA 重启后：优先恢复策略已有状态，再恢复 GUI 的窗口状态和页面；GUI 恢复失败不影响策略状态恢复。

## 10. 测试要求

### 10.1 界面测试

- 完整窗口默认出现在左上角。
- 最小化后只显示状态栏，恢复后字段和页面状态保持不变。
- 五个导航页可切换，当前页有明确选中状态。
- 简洁/专家模式切换不会丢失参数。
- 固定距离和 K 线高度模式正确显示对应字段。
- 草稿修改、取消修改、应用成功和应用失败状态正确。

### 10.2 交易安全测试

- 暂停只阻止新首单，不停止当前订单管理。
- 平仓删挂单必须二次确认；取消确认不产生交易动作。
- 清仓失败时不显示成功。
- 当前订单组参数在应用新配置后仍保持锁定。
- 新配置在下一订单组生效。
- MT4 与 MT5 的相同操作产生相同语义结果。

### 10.3 回归测试

- 现有策略单元测试全部通过。
- 固定距离、K 线高度、单组和多组模式均需验证。
- 终端重启、资金不足、最大反手次数和重复挂单恢复路径不因 GUI 引入回归。
- 在策略测试器中验证 GUI 对交易结果没有额外开仓或平仓副作用。

## 11. 非目标

本阶段不包含：

- 独立桌面客户端。
- 网页远程控制或跨终端控制。
- 修改既有交易策略的开仓、网格、反手算法。
- 自动修改当前订单组的止损止盈。
- 将所有交易历史做成独立报表系统。
