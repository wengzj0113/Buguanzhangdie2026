# 固定距离模式订单防重设计

## 目标

解决固定止盈止损模式中多个EA执行入口同时管理相同账户、品种和订单识别编号，导致首单、反向挂单、网格挂单及止损市价反手重复发送，继而使累计手数异常放大的问题。

本次修改只处理订单执行唯一性和异常保护，不改变以下策略规则：首单方向、循环模式、固定止盈止损距离、K线模式语义、首单及网格手数公式、移动止盈、最大反手次数、有效操作时间和资金不足清仓。

## 根因

固定模式目前采用“查询服务器订单后再发送”的流程，但查询与发送之间没有互斥保护。同一EA被多个图表或同一终端的多个实例以相同账户、品种和订单识别编号运行时，两个实例可能同时查询到没有首单或挂单，并分别发送相同订单。

运行状态只保存一个反向挂单票据 `g_pending_ticket`。当并发产生两张反向挂单后，状态只能跟踪其中一张；未被跟踪的挂单成交时，EA仍可能执行市价反手，形成“挂单已经成交，随后又开市价单”的重复切换。`FindPending()`和`FindGridPending()`只返回第一张订单，也无法发现重复挂单。

## 修复边界

### 1. 交易执行锁

按“交易服务器、账户、品种、订单识别编号”生成独占执行锁文件名。EA在 `OnInit()` 中通过MetaTrader公共文件目录以非共享方式打开锁文件并持续持有句柄；同一台电脑上的第二个MT4/MT5终端或第二个图表实例无法取得相同锁，初始化失败并输出明确日志。`OnDeinit()`关闭锁句柄，终端异常退出时操作系统也会自动释放文件句柄，不遗留永久死锁。

锁覆盖EA整个运行期，不改变指标或价格计算。在策略测试器中，锁文件名额外包含测试图表标识，避免并行回测之间互相阻塞；实盘和模拟盘仍严格执行同账户、品种、订单识别编号唯一管理者规则。

同一终端内，相同账户、品种和订单识别编号只能有一个实例在同一时刻执行交易操作。不同终端之间不共享终端全局变量，必须使用不同订单识别编号；代码同时通过服务器订单扫描降低跨终端并发造成的后续重复风险。

### 2. 首单二次确认

固定模式准备发送首单时，必须在持锁状态下再次确认：

- 没有本EA持仓；
- 没有本EA反向挂单；
- 没有本EA网格挂单；
- 不处于重置或订单组切换状态。

任一条件不满足都禁止发送首单。首单成功后继续使用现有流程设置本组距离、止损止盈和后续挂单。

### 3. 挂单唯一化

新增按类别枚举挂单的逻辑，分别处理反向挂单和网格挂单。每类挂单最多保留一张符合当前订单组预期方向、价格和手数的订单：

- 没有符合预期的订单时，删除错误订单后创建一张正确订单；
- 只有一张符合预期时直接接管其票据；
- 存在多张符合预期时，确定性地保留票据最小的一张并删除其余订单；
- 删除未完成时禁止创建新挂单或发送市价反手，下一Tick重试。

网格挂单和反向挂单分别判断，不能互相删除或覆盖。

### 4. 止损切换幂等

止损时按以下顺序处理：

1. 重新读取所有反向挂单及其历史状态；
2. 若跟踪的反向挂单已经成交并能找到对应新持仓，只接管该持仓；
3. 若反向挂单仍在场，删除本组反向及网格挂单，确认删除完成后才允许市价反手；
4. 市价发送前再次扫描预期方向的新持仓和挂单成交记录；已经存在切换结果时禁止再次发送；
5. 同一止损事件只允许累计一次亏损手数、推进一次循环索引并增加一次反手次数。

当前已有重复主订单时不继续计算更大的下一组手数，也不自动平掉可能属于用户的持仓。EA删除尚未成交的重复挂单、停止新增风险并输出明确错误日志，等待人工确认或重新启动新周期。

### 5. 状态与日志

增加当前订单组切换阶段和唯一切换标识的持久化字段。发生订单发送前保存“准备切换”，成功识别挂单成交或市价成交后保存“切换完成”。EA重启后先根据服务器订单恢复阶段，不能仅凭内存票据重复发送。

日志必须包含账户、品种、订单识别编号、操作阶段、保留票据和删除票据，便于复盘。正常每Tick不输出日志，只在重复订单、锁超时接管、删除失败和状态冲突时记录。

## MT4与MT5一致性

MT5使用终端全局变量条件写入和 `CTrade` 结果码；MT4使用终端全局变量条件写入及 `OrderSend`/`OrderDelete`。两端采用相同的锁键、挂单保留规则、异常暂停规则和止损切换顺序。

## 测试与验收

实施前增加可以稳定复现以下问题的模型测试，并确认测试先失败：

- 两个执行实例在同一Tick同时尝试开固定模式首单，最终只能产生一张首单；
- 两个执行实例同时补反向挂单，最终只能保留一张；
- 两个执行实例同时补网格挂单，最终只能保留一张；
- 反向挂单已成交时不得再产生市价反手；
- 已存在重复挂单时确定性保留一张并删除其余订单；
- 删除重复挂单失败时不得开新挂单或市价单；
- 检测到重复主订单后不再累计亏损手数或放大下一组手数；
- 单实例正常首单、网格、止损切换、循环方向和手数结果保持不变。

最终验收要求Python回归测试全部通过，MT4和MT5均编译为零错误零警告，并通过源码检查确认所有首单、反向挂单、网格挂单和市价反手入口都位于执行锁和服务器状态复核之后。

## 明确限制

独占锁使用MetaTrader公共文件目录，因此能覆盖同一台电脑上的多个MT4/MT5终端。不同电脑之间无法共享本地锁文件；同一账户和品种若必须在多台电脑同时运行，必须为每个EA实例设置不同的订单识别编号。代码会检测服务器上已经形成的重复订单并阻止继续放大，但不能把交易服务器的普通订单发送改造成跨电脑原子事务。
