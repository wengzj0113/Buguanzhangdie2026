# v_enable 可视化界面开关设计

## 目标

为 MT4/MT5 EA 增加 `v_enable` 输入参数，并在不改变交易逻辑的前提下控制可视化 UI：默认值为 `0` 时关闭自定义 UI，设置为 `1` 时启用 MT5 当前自定义 UI。同时对当前 EA 做一次有边界的逻辑 Review，只删除能够确认无用、且不会改变交易行为的冗余代码。

## 已确认的行为

### 参数

```mql5
input int v_enable = 0;
```

MT4 使用同等的 `input int` 声明，以保持两套 EA 的参数兼容。参数名称保留为用户指定的 `v_enable`，并配中文说明。

### MT5

- `v_enable=0`：
  - 不调用 `GuiCreate()`；
  - 不创建、刷新或处理自定义 UI 对象；
  - `OnTick()` 仍然执行完整交易管理；
  - `OnTimer()` 和 `OnTradeTransaction()` 仍然运行，因为它们承担止损后挂单恢复、初始挂单成交协调等交易职责；
  - 不把该参数加入交易配置指纹，避免纯 UI 开关导致交易状态被误判为配置变化。
- `v_enable=1`：保持当前 UI 创建、渲染和图表事件处理行为。
- 参数在 EA 重新加载/重新初始化后生效，不增加运行中切换 UI 的复杂状态。
- `OnDeinit()` 的销毁逻辑保持安全，即使 UI 未创建也可以调用清理函数。

### MT4

- MT4 当前没有 MT5 同款自定义可视化 UI。
- 增加 `v_enable` 仅用于参数兼容和统一配置说明；无论取值为 `0` 还是 `1`，现有 MT4 交易逻辑不变。

## 实施方案

采用“UI 边界隔离”方案：

1. 在 MT4/MT5 输入参数区增加 `v_enable=0`。
2. MT5 `OnInit()` 仅在 `v_enable==1` 时创建 UI；交易初始化和定时器初始化不受影响。
3. MT5 UI 渲染入口和图表事件入口增加开关保护；保护只包围 UI 工作，不包围交易管理。
4. 对 `GuiDestroy()`、UI 刷新和 UI 事件调用做空状态安全检查，确保关闭 UI 时不产生对象操作错误。
5. 增加 Python 源码契约测试，验证 MT4/MT5 均有默认值为 `0` 的参数，并验证 MT5 的 UI 调用受到开关保护、交易定时器仍无条件初始化。
6. 运行完整 Python 测试、MT4/MT5 编译、编译日志检查、差异空白检查，并核对生成二进制文件。

## 冗余代码 Review 边界

只删除以下类型的代码：

- 已被当前调用图证明不可达的函数或分支；
- 重复且已有唯一实现替代的 UI 辅助逻辑；
- 与 `v_enable` 接入后明确变成无效的重复判断。

不做跨平台大规模合并，不重写已经工作的交易状态机，不删除用于兼容历史订单、状态恢复或异常重试的代码。若 Review 后无法证明某段代码是冗余代码，则保留并在交付说明中列出结论。

## 验收标准

- MT5 `v_enable=0` 时图表上不创建自定义 UI，但首单、网格、止损、反手、挂单恢复和订单组切换继续运行。
- MT5 `v_enable=1` 时现有 UI 功能不回归。
- MT4 编译通过，新增参数可在输入页面看到，交易行为不变。
- MT4/MT5 编译均为 0 errors、0 warnings。
- 现有测试全部通过，新增开关契约测试通过。
