# 距离模式拆分为八个 EA 设计

**日期：** 2026-10-11

**状态：** 用户已确认方向，待审阅本规格

## 目标

把现有 EA 的八种距离模式拆成八个固定策略 EA。每个 EA 都能在 MT4 和 MT5 独立编译，参数页只显示该策略会用到的参数；MT5 图表面板也只显示对应策略的参数，不允许在运行时切换距离模式。

订单组、止损切换、循环、网格、移动止盈、手数、篮子、交易时段、点差检查和风控继续由公共交易核心维护。拆分只改变策略入口和参数呈现，不改变各模式现有入场条件、距离计算及订单管理行为。

## 结构

每个平台有一份公共核心和八个可直接编译的 EA 入口。MT4 与 MT5 的交易核心分别维护，以保留各自平台的交易接口和恢复行为。为避免旧图表模板继续加载同名文件却悄悄换成固定策略，现有规范源码 `NoMatterRiseFall_MT4.mq4` 和 `NoMatterRiseFall_MT5.mq5` 继续作为旧的八模式兼容版本；八个新入口均使用明确包含模式名的独立文件名，包括固定距离版（例如 `NoMatterRiseFall_FixedDistance_MT4.mq4`）。新版本主发行包只包含八种策略的 16 个输出（8 种策略 × 2 个平台）；旧版作为单独的迁移/回退工具保留，不计入八个新 EA。

每个入口固定启用一种策略，并包含其参数和策略入口代码；公共核心接收模式入口解析出的入场事件，事件至少带有方向、止损/止盈距离、信号时间和信号标识。K 线每根一次的双向首单 OCO 及 K 线多组行为继续由 K 线策略入口触发，再调用公共订单和订单组服务。箱体突破状态由箱体突破入口继续维护。核心不读取用户可修改的 `距离模式`，也不根据运行时模式值分派策略。

MT5 自定义图表面板保留 `v_enable` 开关和现有用途，但移除距离模式选择，只显示本 EA 可编辑的公共参数及专属参数；面板上以只读文字标明固定策略身份。MT4 继续使用终端原生参数页。MT5 的配置指纹、保存/恢复和 Apply 路径也必须按固定策略身份及该 EA 实际公开的参数重做，不能只把模式选择控件隐藏而继续将旧的八模式配置结构当作当前配置。

## 各 EA 的专属参数

各模式沿用当前默认值和当前交易语义。相同意义的参数尽量沿用现有名称，便于迁移共有设置。

| EA | 参数页和图表面板保留的模式参数 | 首单规则 |
| --- | --- | --- |
| 固定距离 | 固定止损距离、固定止盈距离、首单方向、首单方向确定方式；选择布林带中轨判断时显示布林带周期和标准差 | 按预设方向或价格相对布林带中轨确定首单方向 |
| K 线高度 | K 线最小/最大高度、正向/逆向开单、K 线开单模式、K 线多组 | 每根一次时在前一根 K 线高低点挂双向首单并执行 OCO；每根重复时按突破条件市价入场 |
| 平均 K 线高度 | 平均 K 线根数、平均止损倍数、平均止盈倍数、首单方向和方向确定方式；选择布林带中轨判断时显示布林带周期和标准差 | 使用现有首单方向确定方式，以过去 N 根完成 K 线平均高度计算距离 |
| 长 K 线市价 | 固定止损距离、固定止盈距离 | 保持当前规则：上一根完成 K 线满足现有长度比较条件且不是十字线时，按 K 线实体方向市价入场；比较窗口仍为当前实现的 20 根，不新增参数 |
| 布林带区间 | 布林带周期、标准差、正向/逆向开单、布林带止损百分比、盈亏比、最小/最大止损距离 | 报价触及上轨或下轨时按正向/逆向映射方向入场，区间内不入场 |
| ZigZag 波段 | 深度、偏差、回退、波段最小/最大距离、止损百分比、止盈倍数、正向/逆向开单 | 等价格越过现有确认波段区间边界并移动一个完整波段高度后，按方向映射入场 |
| 箱体高度 | 滚动回看或每日固定时段、回看小时数、时段起止时间、箱体最小/最大高度、首单方向和方向确定方式；选择布林带中轨判断时显示布林带周期和标准差 | 只用 M1 箱体范围计算止损/止盈距离，不增加箱体突破条件；首单沿用当前方向规则 |
| 箱体确认突破 | 识别周期、观察窗口、ATR 周期、触碰 ATR 倍数、上下沿最少触碰、最少完整往返、同侧间隔、宽度范围、突破缓冲倍数、正向/逆向开单 | 沿用当前箱体确认和连续两根收盘确认突破规则，再按方向映射市价入场 |

布林带中轨首单方向参数只出现在实际调用中轨判断的策略中；布林带区间 EA 使用自己的上/下轨触发及方向映射参数。K 线开单模式和 K 线多组参数只出现在 K 线高度 EA 中。

## 公共参数和行为不变量

下列参数继续由所有 EA 提供：循环模式、篮子数量、首单及止损后手数规则、最大反手次数、最大首单点差、止盈移动模式、网格数量及加仓/动态止损选项、网格手数倍数、订单识别编号、订单注释和三个交易时段。MT5 另保留可视化面板开关。某项若在特定入口实际不适用，必须从该入口的 MetaTrader 参数页和 MT5 图表面板同时隐藏。

所有四种循环模式、订单组方向序列、反向预挂单、网格、移动止盈、止损后手数、篮子并行、资金不足清仓、恢复、有效时段和点差行为沿用当前规则。模式各自原来的距离边界、信号时间语义、止损/止盈锁定和失败处理保持不变，不将无效距离回退到其他模式。

## 同品种并行与状态恢复

八个策略须能在同一账户、同一品种并行运行。16 个新策略/平台输出使用彼此不同的默认订单识别编号，并为旧版八模式 EA 保留其当前默认编号；运行者手动修改后仍须保持唯一，且订单识别编号须为 MT4 `int` 可表示的正值。初始化时应检测同一终端上同账户、同品种、同编号的重复实例并拒绝后启动者；即使两个实例属于同一策略，也不能同时管理同一编号的订单。新实例若发现该编号已有持仓/挂单但没有匹配的固定策略状态，也必须停止并要求明确迁移，不能按编号直接认领。持仓和挂单扫描仍按平台、账号、品种和订单识别编号筛选；状态文件/全局变量和执行锁还要纳入固定策略身份及状态版本，避免不同入口共享恢复数据或锁。不能只依赖订单注释来隔离，因为经纪商可能截断或改写注释。默认编号表、冲突检查和多实例重启后的冲突恢复规则需在实施计划中具体化。

活动订单组不做跨配置自动接管承诺。最安全的常规升级路径是让旧八模式版本继续管理已有组，直到该实例空仓且无挂单，再切换到固定策略版；新版本安装/启用时不得覆盖已在运行的旧版文件。若确需恢复活动组，必须由实施阶段定义并测试一条明确的迁移路径：停掉旧实例、验证原模式与组状态、验证新旧配置及状态版本兼容后才允许接管；任何不匹配都必须拒绝接管且不得清仓或继续管理。旧版配置指纹包含所有模式参数，可能因已隐藏参数不同而不兼容。旧 `.set`、图表模板和预设文件不得被宣称可直接迁入固定模式 EA；EA 文件名决定固定策略，旧的距离模式字段不能覆盖它。常规发布文档要说明旧版何时退役、如何等待空仓、以及如何回退。

策略身份不能仅由订单识别编号的默认值暗示：订单编号用于终端订单隔离，固定策略 ID 用于状态/锁隔离和恢复校验。若同一终端发现编号冲突，必须提示冲突的策略身份并阻止新的冲突实例交易；处理终端崩溃后残留的实例注册信息时，不得把仍在运行的实例误判为过期并抢占。订单编号若撞上旧版或其他 EA 遗留的订单/状态，也必须默认拒绝接管。

## 构建、文档和验证

构建脚本须支持单独编译一个模式，以及编译全部 16 个新输出；现有 `-Target Both` 命令仍编译两份规范的旧版兼容源码，满足项目构建约定。规范源码发生改变时，按项目指令先运行自动化测试，再执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\compile-mql.ps1 -Target Both
```

并额外编译全部拆分入口。成功标准为每个平台所有目标均无编译错误，且预期 `.ex4`/`.ex5` 输出已刷新；记录并报告警告和产物路径。打包时明确区分八个新 EA 与旧版兼容 EA，避免同名覆盖；ZigZag EA 的发行包还须带上对应平台所需的 ZigZag 指标源码/编译文件及安装说明，其余 EA 不应要求该依赖。更新 README 和 HTML 使用手册，说明八个 EA、每个 EA 的参数、固定策略身份、唯一编号冲突规则、旧版保留与退役时机、旧 `.set`/模板的兼容边界、活动订单组迁移方式和 ZigZag 依赖。旧 `.set` 中名称和类型均匹配的公共参数可作为手动迁移参考；专属参数须按新 EA 核对，旧距离模式字段不决定新 EA 的策略。

自动化验证比较拆分前的各模式和拆分后的固定入口，覆盖入场信号、方向映射、距离边界、信号时间/去重、OCO、多组、篮子和公共订单组管理；还要覆盖配置保存后重启、活动组状态版本校验、缺少 ZigZag 依赖、MT5 面板 Apply/恢复，以及同终端重复编号被拒绝。另验证各 EA 只暴露公共参数与其专属参数，且八个固定策略使用默认编号时在同一品种上状态与订单隔离。测试器无法覆盖的真实终端行为需用对应平台进行确认。

## 范围外

- 不新增交易策略或改变任何模式的入场、距离和订单管理规则。
- 不新增长 K 线比较窗口等当前没有的可调参数。
- 不改变 MT4/MT5 平台交易能力差异，也不把两平台实现强行合并为单一源码。
